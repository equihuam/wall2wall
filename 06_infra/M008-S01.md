## Configuración y propiedad

local_state/m008-s01-config.json es configuración ignorada preparada por el
arquitecto: conda, bash, prefix, powershell, parent y marker. Las rutas concretas
no pertenecen al producto portable. parent es almacenamiento persistente externo
a repositorios y temporales; marker no debe existir antes del único despacho.
No cambiar la configuración ni reutilizar un marcador consumido.

El adaptador 06_infra/m008_native/windows.ps1 selecciona explícitamente Conda,
Git Bash y el prefijo Windows existente. Ejecuta Python nativo mediante conda run;
no copia ni reinstala el entorno. A diferencia del wrapper histórico windows.ps1,
la selección no depende de un prefijo relativo a la instantánea. PATH y variables
se acotan al proceso y se restauran al terminar. Se conservan intactos el wrapper
D014, los locks y la copia Windows histórica.

El worker exige win32, Python 3.11.16 y correspondencia de sys.prefix/intérprete;
comprueba imports core/extras desde ese prefijo. Coteja 103 registros Conda con
nombre, versión, build y hash registrado, 51 versiones pip y las identidades
externas de Git Bash. El cotejo pip no revalida los hashes de los artefactos
originales descargados: esos hashes siguen siendo evidencia histórica.

## Instantánea y persistencia

El inventario S01 añade verify_evidence.py a los once archivos base: doce entradas
exactas, con rutas relativas, tamaños y SHA-256; manifiesto ligado a HEAD y bytes
arquitectónicos actuales. La materialización copia bytes sin normalizar LF/CRLF.
Rechaza escapes, enlaces/reparse points, nombres reservados, colisiones de case,
destinos existentes e identidades distintas. La longitud admitida es hasta
200 caracteres de ruta absoluta; no se afirma soporte de rutas mayores.

dispatch crea una raíz nueva y subdirectorios separados snapshot, scratch,
evidence y logs antes del proceso. Conserva native-config.json, started.json,
dispatch-result.json, summary.json, manifiesto, suite.log, native.xml y receipt.json.
El puntero ignorado local_state/m008-s01-native-attempt.json enlaza invocation,
raíz y configuración. Los originales no se borran, ni se reutilizan .pending,
marcadores o directorios. Sólo se cuentan árboles propios, nunca prefijos/cachés
ni almacenes ajenos. Picos de scratch/RSS y tokens permanecen unknown si no medidos.

## Secuencia coder y oficial

Los comandos siguientes describen la reserva D035, no autorizan repetirla.
El coder ejecuta una sola vez mediante linux.sh:

    python 06_infra/m008_native/dispatch.py --s01 --config local_state/m008-s01-config.json

No ejecutar el despachador histórico sin --s01. Tras éxito observado, leer el
puntero local y copiar exactamente los bytes de summary.json externo a
06_infra/m008-s01-native.json, sin añadir rutas privadas ni modificar el resumen.
Ese resumen enlaza invocation, HEAD, manifiesto, recibo win32, testigo before=after
y hashes de logs/JUnit. El recibo nativo sigue siendo distinto del recibo Linux.

Después de completar documento y copia, el coder consume una sola comprobación:

    python 06_infra/m008_native/verify_evidence.py --phase next

Sin marcador previo selecciona coder. Guarda resultado/log externos con puntero
local_state/m008-s01-coder-verification.json. No volver a invocarlo: tras éxito,
next seleccionaría official y consumiría la reserva del arquitecto.
Después de coded ordinario, sólo el arquitecto ejecuta:

    python scripts/verify.py M008-S01 --timeout 120

El full congelado ejecuta el mismo gate --phase next en fase official y conserva
invocation/hashes en el recibo Linux. No lanza Windows otra vez. Verifica copia
portable exacta, finalización exit0 dentro del plazo, inventario obligatorio,
fuentes actuales/snapshot, testigo, runtime, locks, artefactos, JUnit y encabezados.
Rechaza evidencia ausente, obsoleta, alterada, incompleta o proceso no terminado.

## Fallos y límites

Fallo, timeout o desconexión consume el intento: detener, preservar logs/config,
punteros y resultado unknown cuando corresponda; no repetir, limpiar evidencia,
matar procesos ni corregir código bajo este contrato. El arquitecto debe resolver
la causa y obtener autoridad nueva si necesita cambios o ejecución adicional.
El gate coder fallido no permite avanzar a official. Los encabezados canónicos
AGENTS.md se verifican sobre el scope explícito arquitectónico; reviewer evalúa
su veracidad y toda la baseline, no sólo este documento.

No se ejecutan fits, suites científicas, builds, canaries, Snakemake, production,
validated, réplicas, instalaciones ni red. No se modifica el entorno ni se hace
commit/push. Un resultado satisfactorio de frontera no es aceptación automática,
soporte integrado Windows, equivalencia de plataformas o publicación. M008-S02
conserva la integración del workflow y comparación con atol=rtol=1e-5.
